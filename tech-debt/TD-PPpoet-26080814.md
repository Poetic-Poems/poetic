**Severity:** Low

`src/tools/serve-static.js` has no `module.exports`.
`directoryExists(ROOT_DIR)`/`process.exit(1)` (lines 224-227) and
`http.createServer(...)` (line 229) both run as module-load side effects.
`test/serve-static.test.js:65` compiles the file's source into a throwaway
`Module` object per test (`new Module(SERVE_STATIC_PATH, module)`) instead
of `require`-ing it. The graceful-shutdown handlers are keyed off
`Symbol.for('poetic.serveStatic.shutdownHandlers')` on the global `process`
object (`:399-411`) purely so re-loading the module per test replaces
rather than accumulates `SIGINT`/`SIGTERM` listeners.

This is the same finding as the 2026-07-21 and 2026-07-31 reviews' F-ARCH-02
(there addressed by R-10 both times) — unfixed across three consecutive
reviews now, unchanged in substance.

**Why it matters.** Proportionate today, but every feature this module has
grown (favicon/all-poems concatenation, then graceful shutdown) has
invented a new testability workaround rather than the module becoming
importable — three consecutive reviews carrying the same open
recommendation without action sets precedent for "the next feature invents
workaround #3."

**Suggested fix:** Extract a `createServer(rootDir, opts)` factory
returning `{ server, close }` with no port binding or process-level signal
registration at module scope; keep the `require.main === module` CLI entry
point as the only eager caller. `test/serve-static.test.js` can then
`require()` the module directly. Budget time to update the test suite
alongside the production change.
