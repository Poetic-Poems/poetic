**Severity:** Low

`src/tools/blogger-auth.js`'s `waitForCode()` checks
`expectedState && returnedState !== expectedState` in two places —
`:356-362` (the `error` branch) and `:374-380` (the `code` branch) — with
identical condition, identical response body, and identical rejection
message. Raised as a non-blocking observation on PR #165
(https://github.com/Poetic-Poems/poetic/pull/165#issuecomment-5275828115),
which added the `error`-branch copy to close a CSRF gap that branch
previously lacked, matching the `code` branch's existing check rather than
hoisting both into one place. Left as-is there because both paths are
directly covered by `test/blogger-auth.test.js`, but duplicated security
logic can still diverge silently if one copy is edited and the other is
missed.

**Suggested fix:** Hoist the guard above the `if (error)` / `if (code)`
branches in `waitForCode()`'s request handler, so it runs once per request
before either branch's own logic, and delete the two inline copies. The
existing state-mismatch tests should pass unchanged since the guard's
behaviour is the same, just checked once instead of twice.
