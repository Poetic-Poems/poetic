**Severity:** Low

Four small, independent gaps, bundled as one item because each is a
standalone, few-line documentation or config addition with no shared code
path:

1. **No CI/coverage status badge in README.** `README.md:1-13` has no
   `![CI](...)`/shields.io badge near the title/logo. Carried forward from
   the 2026-07-31 review's R-13 bundle (there F-CI-02/F-TOOL-02 under
   earlier numbering).
2. **No documented rollback/yank path for a bad tagged release.**
   `.github/workflows/release.yml`'s `release` job (lines 75-121) tags and
   publishes unconditionally the moment `package.json`'s version changes on
   `main`; no rollback/yank language exists in `docs/BUILD.md`, `README.md`,
   `CLAUDE.md`, or `CHANGELOG.md`. Low risk — not a live service, consumer
   repos pin via `.poetic-version` — but no written procedure exists to
   reach for under pressure.
3. **No `.github/PULL_REQUEST_TEMPLATE.md`.** `find .github -iname
   "*TEMPLATE*"` returns nothing. Matters mainly if/when external
   contribution becomes real, or to standardise the PR-description-carries-
   through-to-squash-commit convention `CLAUDE.md` relies on.
4. **`docs/YAML-SCHEMA.md`'s segment-label example still shows brackets the
   real schema doesn't store.** `docs/YAML-SCHEMA.md:23,27` shows `label:
   "[Verse 1]"` and `label: "[Chorus]"`; real generated YAML
   (`src/poems/yaml/_example.yaml`, `examples/example-blockquote.yaml`) has
   bracket-free labels like `label: Verse 1` — the `[...]` wrapping is added
   only at render time (`src/templates/_poem-content.pug:73`). A reader
   copying the example literally would double-wrap the rendered label on
   first build.

**Suggested fix:** Add a `build-poems.yml` workflow badge near README's
title; a short "if a release is bad" paragraph in `docs/BUILD.md` or
README; an optional PR template under `.github/`; and correct
`docs/YAML-SCHEMA.md`'s example to bracket-free `label:` values matching
every other example already in the same file.
