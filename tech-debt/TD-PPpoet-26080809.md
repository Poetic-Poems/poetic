**Severity:** Low

Two small, independent duplications found in the same CODE-dimension pass:

1. `footer.js:48-60` (`resolveFooterSourcePath`) and `build-blogger.js:49-86`
   (`resolveTemplatePath`) each independently reimplement "resolve via
   `safeJoin`, check `isWithinRoot`, warn-and-fall-back" on top of the
   shared `path-guard.js` primitives, but with different shapes:
   `footer.js` has one fallback (default footer, returned immediately on
   containment failure); `build-blogger.js` now has a four-tier cascade
   (explicit config key → canonical `blogger-template.html` → any
   `*.template.html` in `publicDir` → default). This was already flagged in
   the 2026-07-31 review (its F-CODE-01/R-09) and has diverged further
   since, not converged — `build-blogger.js`'s side has grown more
   elaborate. `path-guard.js` still exports only `safeJoin`/`isWithinRoot`,
   no combinator for the "resolve + contain + warn + fall back" composition
   both call sites perform by hand.

2. `date-utils.js`'s `toISODate()` (`:66-83`) centralises "a YAML-parsed
   date may come back as a string or a JS `Date`" and guards with
   `isNaN(dateStr.getTime())`, returning `null` on an invalid date.
   `sync-blogger.js:936-940` reimplements the same check inline (`raw.date
   instanceof Date ? raw.date.toISOString().slice(0, 10) :
   String(raw.date || '')`) without that guard —
   `new Date(...).toISOString()` throws a `RangeError` on an invalid `Date`
   instance rather than degrading gracefully. Also previously flagged
   (2026-07-31's F-CODE-03), unchanged since.

**Why it matters.** Both path-containment copies are correct today, but
nothing structurally prevents the next edit to one from silently not being
mirrored in the other. The date-coercion gap is low practical risk (a
malformed `date` field would need to survive YAML parsing as an actual
invalid `Date` object) but is the third independent reimplementation of
this exact coercion in the codebase, and the one outside `date-utils.js`
remains the one without the safety guard the others have.

**Suggested fix:** Extract a shared `resolveContainedConfigPath(repoRoot,
configuredPath, { fallback })` helper into `path-guard.js`, used by both
`footer.js` and `build-blogger.js`. Replace `sync-blogger.js:936-940`'s
inline date branch with `toISODate(raw.date) || ''`.
