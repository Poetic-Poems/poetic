title: yaml-to-poem loses fidelity on real-world poems — unbalanced `<p>`, re-escaped quotes, and a hard-coded default author
status: in-progress
filed: 2026-08-02
---

`.poem` → YAML → `.poem` is not a fixed point for poems that use HTML-bearing
analysis/postscript sections, line-leading double quotes, or no author line.
Running the round-trip twice keeps changing the text, so
`node src/tools/yaml-to-poem.js --all` still cannot be a clean no-op on a real
collection even after TD-PPpoet-26080102 removed the stray `====` markers.

Measured against the `fragments-and-unity` corpus (75 poems), 9 are unstable
between the first and second pass; the same 9 are unstable both before and
after `#144`, so this is long-standing and separate from that fix.

Three distinct causes:

1. **Unbalanced `<p>`.** `convertHtmlToPlainText()`
   (`src/tools/yaml-to-poem.js`) strips a *leading* `<p>` but leaves the
   matching `</p>`, so re-parsing sees unbalanced markup and the next pass
   emits `<p>…</p></p>`. Affects `{Full}`, `{Synopsis}` and postscript bodies
   whose content is more than one simple paragraph. Seen on
   `guilty.poem`, `divide-and-lose.poem`, `at-the-end-of-myself.poem`,
   `my-shepherd-2026.poem`.

2. **Re-escaped quotes.** A line beginning with `"` comes back as `\"` on the
   second pass, and gains another backslash on each pass after that. Seen on
   `flying-high.poem`, whose verses open with an unclosed quotation mark.

3. **Hard-coded default author.** `writeHeader()` omits the author line when
   `this.data.author === 'A Poet'` — the value this repo's own
   `src/poems/poem/.shared.poem` happens to define. A consumer's `.shared.poem`
   is user-owned and defines its own `${author}`, so there the omission is
   lossy in one direction (a poem whose author *is* "A Poet" loses the line and
   re-reads as the consumer's default) and noisy in the other (every poem that
   inherited its author gains an explicit author line it never had). The
   sentinel should be "whatever the applicable `.shared.poem` resolves
   `${author}` to", not a literal.

Why it matters: `yaml-to-poem.js` is the reverse tool — the forward build
(`.poem` → YAML → HTML) is unaffected, so no published site is wrong today.
But the tool is unusable for its stated purpose (regenerating `.poem` sources,
e.g. after editing YAML) while its output differs from its input for reasons
unrelated to the edit, and the diff noise hides real changes.

Where: `src/tools/yaml-to-poem.js` — `convertHtmlToPlainText()` (1), the line
escaping applied when writing version lines (2), and `writeHeader()` (3).

Suggested fix: take the three causes separately, each with a fixture under
`test/fixtures/round-trip/` (the directory added alongside this item) covering
the shape it breaks on. For (3), resolve the default author from the parsed
shared-poem variables rather than comparing against a literal.

Cross-references: `test/yaml-to-poem.test.js` cites this ID in the comment
explaining why the corpus-walk test is skipped in consumer repos — when this
is resolved, revisit whether that test can run everywhere, and remove the
citation.
