**What.** `scripts/next-tech-debt-id.pl` computes the next free NN by
scanning a ref or the working tree; it reserves nothing. Its own docstring
concedes the gap — it "cannot see IDs allocated on unmerged claim branches —
check open pull requests and td/* branches before relying on the result" —
and that check is manual prose in `TECH-DEBT.md`'s "Filing an item" step 1.
Two writers on different branches (or different nodes) inside the same
window can each be handed the same ID, and each passes `td-check.pl`
locally.

**Why it matters.** The registers are worked by concurrent agents, and
same-day multi-writer filing is routine, not theoretical: on 2026-08-08
three writers filed five `PPagop` records, and an interactive session
collided twice — see the review discussion on agent-ops PR #257. The
existing backstop (the add/add filename conflict named in "Filing an item")
only fires when both sides *add* the file. A writer whose clone already
contains the taken ID overwrites instead: git records a modification, not
an addition, so there is no conflict, `td-check.pl` still sees a
well-formed register, and the append-only CI guard does not fire because
nothing was deleted or renamed. An open item's body silently becomes a
different item's body — the register's one job, being a permanent record,
is exactly what breaks.

**Where.** `scripts/next-tech-debt-id.pl` (canonical here; consumer
registers such as agent-ops hold byte-identical copies guarded by their
td-tooling-drift workflows, so the fix lands here and propagates);
`TECH-DEBT.md` "Filing an item"; `docs/TECH-DEBT-REGISTER.md`;
`.github/workflows/tech-debt-register.yml` for the CI half.

**Suggested fix.** Two parts, the first reusing the primitive the register
already trusts:

1. A `reserve-tech-debt-id` script that makes allocation atomic the same
   way claiming already is ("Claiming an item" step 3: the `td/<id>` branch
   push is the race-safe lock). Loop: compute a candidate from
   `--ref origin/main` plus `git ls-remote origin 'refs/heads/td/*'`;
   create and push `td/<id>` from `origin/main`; a rejected push means
   another writer holds that ID — increment NN and retry; a successful push
   is a fleet-wide reservation. Filing and claiming then share one
   mechanism: the reservation branch is the filing PR's branch, and
   abandoning the filing deletes the branch, releasing the ID. Update
   "Filing an item" to call the script instead of prescribing the manual
   skim.
2. Optionally, a CI guard for the failure mode no reservation can prevent
   (a stale writer overwriting an already-merged record): fail a pull
   request that materially rewrites an **open** item's body while leaving
   its `status:` untouched — lifecycle edits are frontmatter-only by
   design, so a body rewrite without a resolution is either a collision or
   a policy breach, and both deserve a red check.

An ID grammar that cannot collide by construction (node or session entropy
in the ID) was considered and rejected: it would break the date+NN
readability and the alphanumeric-order-equals-allocation-order property
`docs/TECH-DEBT-REGISTER.md` specifies.

Referenced from: agent-ops PR #257 (review discussion recording the
2026-08-08 collisions).
