**Severity:** Medium

`src/tools/sync-blogger.js` exports 20 functions (`:1013-1033`);
`test/sync-blogger.test.js` imports/tests 15 (`:20-34`) — every pure helper
plus the two orchestration functions `main()` drives (`syncPoem`,
`processRemovals`), the latter via `global.fetch`-mocked integration tests
covering create/update/dry-run/draft/delete/keep branches.

Untested: `getAccessToken` (`:426`), `listAccessibleBlogs` (`:458`),
`listAllPosts` (`:481`), `diagnoseBloggerFailure` (`:767-777`), and
`main()` itself (`:885-1012`) — the per-poem loop building
`isoDate`/`desired`/`currentSlugs` and the top-level try/catch calling
`diagnoseBloggerFailure`. These four helpers are called from no site except
`main()`, so nothing exercises them even indirectly through the tested
`syncPoem`/`processRemovals` paths. A fresh `c8` run puts `sync-blogger.js`
at 80.96% lines / 81.48% funcs, with the uncovered ranges landing exactly
on this set.

**Why it matters.** Unlike `build-poems.js`'s/`build-all-poems.js`'s
untested `main()` bodies — both invoked by `npm run build`, itself a
required CI step, giving them an effective smoke test — `sync-blogger.js`'s
`main()` is invoked only by `.github/workflows/sync-blogger.yml`, which
this framework repo's own (absent) `.poetic-config.yaml` never enables, so
the workflow's `precheck` step always skips it here. The only place this
code path runs for real is a consumer repo's production workflow,
publishing to a live Blogger blog with real credentials. A regression in
the untested glue — e.g. the ad hoc date coercion tracked separately as
`TD-PPpoet-26080809` (F-CODE-02) — would not be caught by this repo's suite
or CI, surfacing first as a broken publish run.

**Suggested fix:** At minimum, add direct unit tests for
`getAccessToken`/`listAllPosts`/`listAccessibleBlogs`/`diagnoseBloggerFailure`
with mocked `fetch`, matching the existing `createPost` test pattern.
Ideally, refactor `main()` to accept injectable dependencies (mirroring
`build-poems.js`'s `{ poemsDir, publicDir }` override pattern) so a test can
drive the full per-poem loop with `global.fetch` mocked.
