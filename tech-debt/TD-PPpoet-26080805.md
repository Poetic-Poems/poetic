**Severity:** Medium

`README.md:207-216`'s "Convert to YAML (and back)" example runs single-file
`poem-to-yaml.js`, then `--all`, then `yaml-to-poem.js
src/poems/yaml/my-poem.yaml`, all in one code block. Reproduced directly in
a scratch clone: the single-file command writes YAML *next to the source*
`.poem` file, in `src/poems/poem/`, because `poem-to-yaml.js:150` computes
`outputFile = args[1] || inputFile.replace('.poem', '.yaml')` when no
explicit output path is given. The third command in the block then fails:
`Error: ENOENT: no such file or directory, open
'src/poems/yaml/my-poem.yaml'`.

Running all three commands in sequence, verbatim, happens to succeed — the
middle `--all` command incidentally also converts the same file, populating
`src/poems/yaml/my-poem.yaml` before the third command runs, papering over
the bug for that one specific execution path. This makes the defect
intermittent-looking rather than a guaranteed reproduction, which may be
why it has survived two prior review cycles (2026-07-31, and now this one)
undetected by casual reading — but a reader who treats the first two
commands as alternatives ("convert one file" *or* "convert all files")
rather than a mandatory sequence, and skips straight to the third, still
hits the ENOENT.

This item was previously named as this review's R-05 in the 2026-07-31
review (`reviews/project-review-2026-07-31/03-recommendations.md`), but no
tech-debt item was filed for it at that time and no PR has since addressed
it — filing it now so it is trackable via the register, not only via a
dated review folder.

**Suggested fix:** Either change the single-file example to pass an
explicit output path (`node src/tools/poem-to-yaml.js
src/poems/poem/my-poem.poem src/poems/yaml/my-poem.yaml`), or drop the
single-file variant from this example and lead with `--all` (which
`docs/POEM-TO-YAML.md` already does correctly). Verify by actually running
the corrected example end-to-end.
