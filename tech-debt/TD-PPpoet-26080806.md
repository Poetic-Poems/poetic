**Severity:** Medium

`README.md`'s "Contributing" section (`:327-358`) covers the PR/branch-
protection process and Conventional Commits format in detail, but a
full-text grep of `README.md` for `npm test`, `npm run lint`, `npm run
coverage`, `npm run check`, `check:licenses` returns zero matches. No
`CONTRIBUTING.md` exists anywhere in the repo. These five commands — the
things CI actually gates on — remain documented together only in
`CLAUDE.md:44-48`, a file explicitly written for AI agents, not a human who
clicked "Use this template."

**Why it matters.** Not a hard blocker — CI catches the same problems
within about a minute — but a human contributor's first PR iteration
routinely surfaces failures a two-line note would have caught locally
first. This has now been flagged across three consecutive project reviews
(2026-07-21 onward under earlier numbering, 2026-07-31 as R-07, now this
review as R-05) with no PR addressing it; filing it as a tracked item so it
surfaces via the register rather than only via dated review folders.

**Suggested fix:** Add a short "Local development" subsection to README's
Contributing section (or a new `docs/CONTRIBUTING.md` linked from it)
listing `npm test`, `npm run lint`, `npm run coverage`, `npm run check`,
`npm run check:licenses`. Can mirror `CLAUDE.md`'s "Build commands" list.
