**Severity:** Medium

`blogger-auth.js` is the one CLI in `src/tools/` with a real `--help`
(confirmed by running it — prints usage and an options table). No other
tool recognises the flag:

- `node src/tools/poem-to-yaml.js --help` → `Error: ENOENT: no such file or
  directory, open '--help'` (exit 1) — `--help` is read as the input
  filename (`poem-to-yaml.js:150-160`).
- `node src/tools/yaml-to-poem.js --help` → the identical ENOENT-as-filename
  failure.
- `node src/tools/build-poems.js --help`, `node src/tools/poem-to-raw.js
  --help`, `node src/tools/sync-blogger.js --help` all silently ignore the
  flag and run their normal default action instead — including a real
  build, in the first case.

**Why it matters.** A newcomer's first instinct when unsure of a tool's
arguments — the exact audience `docs/POEM-TO-YAML.md`/README's authoring
workflow section is written for — is undermined twice over: two tools
answer with a confusing raw Node ENOENT error instead of their own usage
string (which they already print for zero arguments), and three more
silently *do something*, including a filesystem write, rather than
nothing. `blogger-auth.js` shows the project already knows what good CLI
`--help` looks like; it just isn't applied consistently.

**Suggested fix:** Add a shared `--help`/`-h` check (or a tiny shared
helper) at the top of each tool's `main()`, ahead of positional-argument
parsing, that prints the existing usage string and exits 0 with no side
effects.
