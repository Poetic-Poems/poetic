**Severity:** Medium

`convertHtmlToPlainText` (`src/tools/yaml-to-poem.js:583-688`, ~124 lines)
is a block-by-block dispatcher with 7 branches (headings ×4 near-identical,
multi-paragraph, "peeled" tail element, literal-block wrap, plain-text
fallback), each guarded by dense prose explaining a specific historical bug
it exists to prevent — the comments cite `TD26072401`, `TD26072502`, and
`TD-PPpoet-26080201` by ID inline (e.g. lines 624-627, 639-643, 656-660).
`splitParagraphRun` (line 707+) documents that an earlier, simpler regex
was CodeQL-flagged for catastrophic backtracking and had to be rewritten as
a manual scan — this is the classic shape of a subsystem that grew by
accretion (each new poem shape breaking the converter, patched with a new
branch) rather than being designed against a grammar up front, reinventing
a narrow slice of HTML→Markdown conversion by hand in a codebase that
already depends on `markdown-it` for the opposite direction.

Within it, `:605-616` has four consecutive `if`/`else if` branches for
`<h5>`/`<h4>`/`<h3>`/`<h2>`, each doing the same
match-then-strip-then-push sequence — the only differences across the four
are the tag digit and the number of `#` characters pushed (`###`, `##`,
`#`, `#` — h2 and h3 both collapse to a single `#`, an asymmetry easy to
miss as intentional vs. a copy-paste slip).

**Why it matters.** Currently well-mitigated by strong round-trip test
coverage (`test/yaml-to-poem-roundtrip.test.js` exercises most of these
branches directly), so this is not an active bug — but the pattern (bespoke
regex/string-splitting logic, patched reactively per newly-discovered edge
case, 3 TD IDs deep already) is exactly the shape that tends to keep
finding new edge cases in unusual HTML shapes (nested lists are explicitly
called out as falling through to a "verbatim passthrough" fallback rather
than being handled). The heading duplication means a future change to
heading detection has four call sites to update in lockstep instead of one.

**Suggested fix:** Collapse the four heading branches into one small loop
or lookup table (`{ h5: '###', h4: '##', h3: '#', h2: '#' }`) parameterised
by tag digit. No urgent action on the broader function structure given its
test coverage; worth a note for whoever next touches this file to consider
whether the next round-trip bug is better spent hardening incrementally
(current path) or reconsidering the structure.
