title: Open-item rewrite guard exempts wholesale replacement of an empty body
status: open
filed: 2026-08-13
---

**What.** `scripts/check-tech-debt-open-rewrites.pl` exempts strict appends
(head body starts with the base body byte-for-byte). Every string has the
empty string as a prefix, so an open item whose body is empty at the merge
base can be wholesale-replaced with entirely different prose and the guard
exits 0 with `no open-item body rewrites`. Found and verified in the
second-round review of PR #166
(https://github.com/Poetic-Poems/poetic/pull/166#issuecomment-5276269816).

**Why it matters.** The collision the guard exists for — a stale clone
overwriting an already-merged record as an ordinary content modification —
is exactly what such a replacement would look like. The reasoning the
append exemption rests on ("a collision can never look like a strict
append") holds only for a non-empty victim body. Exposure today is nil: no
open item in the register has an empty body, and
`docs/TECH-DEBT-REGISTER.md` specifies a free-prose body for every item.
But nothing enforces that — `td-check.pl` does not require a non-empty
body, and the items migrated from the old single-file register are
precedent for empty bodies existing.

**Where.** `scripts/td-check.pl` (primary fix);
`scripts/check-tech-debt-open-rewrites.pl` (hardening);
`test/tech-debt-scripts.test.js`. Both scripts are canonical here;
consumer registers hold byte-identical copies guarded by their
td-tooling-drift workflows, so the fix lands here and propagates.

**Suggested fix.** Two changes, landed together or filing-side first:

1. `td-check.pl` requires a non-blank body — contains a non-whitespace
   character, not merely non-zero length, since a whitespace-only body
   passes a length test and still leaves the byte-prefix exemption
   near-vacuous — for any item whose `status:` is not `resolved` or
   `not-debt`. That makes "open item, empty body" unrepresentable on
   `main` via any pull request, restoring the append-exemption reasoning
   unconditionally; the `resolved`/`not-debt` carve-out grandfathers the
   migrated legacy items.
2. The append exemption in `check-tech-debt-open-rewrites.pl` additionally
   requires `$base_body =~ /\S/`. With (1) in place an empty-bodied open
   stub can no longer be filed, so this blocks no legitimate workflow; it
   fires only if the td-check invariant was bypassed (a direct push to
   `main`, a legacy anomaly), where a red check and a human look is the
   wanted behaviour — and it removes the guard's dependence on another
   script's invariant.

Ordering matters: (2) without (1) recreates the original PR #166 problem
in miniature — an empty-bodied open item whose only editing path is a
false `status:` move.

Referenced from: poetic PR #166 (second-round review comment recording
the gap).
