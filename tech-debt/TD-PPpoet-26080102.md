title: yaml-to-poem writes trailing `====` markers for empty sections, so `--all` never round-trips a .poem file unchanged
status: open

`YamlToPoemConverter.writeAudio()` and `writePostscript()`
(`src/tools/yaml-to-poem.js`) each emit their `====` section terminator
*outside* the `if (this.data.audio)` / `if (this.data.postscript…)` guard,
and `writeVersions()` emits one unconditionally. A poem with no audio and
no postscript therefore comes back with three bare `====` markers appended
that its source never had. `docs/POEM-SYNTAX.md` says a divider is required
"only if there is subsequent non-empty content", so the extra markers are
tolerated by `poem-parser.js` (the round-trip tests in
`test/yaml-to-poem-roundtrip.test.js` pass because they compare *parsed
objects*, not text) — but they are not what an author writes.

Why it matters: with `--all` now resolving real directories
(`#143`, R-02), `node src/tools/yaml-to-poem.js --all` rewrites every file
in `src/poems/poem/` and can never be a clean no-op. On this repo's own
corpus it leaves `src/poems/poem/a-poem-kept.poem` modified with three
appended `====` lines even though nothing about the poem changed; a
consumer repo running it over a real collection gets the same churn across
every poem, which makes the tool's output impossible to distinguish from a
real edit in a diff.

Where: `src/tools/yaml-to-poem.js` — the `this.addLine('====')` calls at
the end of `writeVersions()`, `writeAudio()` and `writePostscript()`.

Suggested fix: emit each section's `====` only when a later non-empty
section actually follows (matching the spec's rule), and add a fixture test
asserting that `.poem` → YAML → `.poem` is byte-stable for this repo's own
`src/poems/yaml/` corpus, so the noise cannot come back unnoticed. Removing
the markers changes the single-file conversion output as well, so the
existing `test/yaml-to-poem.test.js` expectations need reviewing in the
same change.
